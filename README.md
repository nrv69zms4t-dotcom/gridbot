# gridbot — спотовый грид-бот для крипты (R&D)

Классическая **статическая сетка** (grid trading) на споте: N ценовых
уровней в диапазоне `[lower, upper]`, BUY-лимитки ниже текущей цены,
SELL-лимитки выше (обеспечены стартовой покупкой базового актива по
рынку). Исполнение BUY на уровне `i` ставит SELL на уровень `i+1`;
исполнение SELL на уровне `j` ставит BUY на уровень `j-1`. Прибыль
сетки — шаг уровня × количество минус комиссии за каждый завершённый
круг buy→sell.

Три режима:

| Режим | Модуль | Что делает |
|---|---|---|
| **backtest** | `gridbot.backtest` | Исторические свечи Binance → отчёт |
| **paper** | `gridbot.paper` | Живые цены (public REST), симулированные исполнения, персистентное состояние |
| **live** | `gridbot.live` | **Реальные ордера** на Binance spot (testnet по умолчанию, mainnet — с явным подтверждением) |

Требования: Python 3.11+, `pandas`, `requests`, для тестов `pytest`.
Для backtest и paper API-ключи не нужны — только публичные эндпоинты
Binance. Для live нужны ключи с правами «чтение + спот-торговля»
(см. раздел про live ниже).

## Скачивание данных

Данные качаются автоматически при первом бэктесте и кэшируются в
`gridbot/data_cache/*.csv`. Вручную:

```python
from gridbot.data import load_klines
df = load_klines("BTCUSDT", "1h", "2025-05-01", "2025-07-01")
# колонки: open_time (UTC), open, high, low, close, volume
```

Пагинация по 1000 свечей, пауза между страницами, при 429 — сон по
`Retry-After`.

## Если Binance отвечает 451 (региональная блокировка)

В некоторых регионах `api.binance.com` (и даже testnet) возвращает
HTTP 451. Для **публичных рыночных данных** (цены, свечи, фильтры
символов) бот в этом случае автоматически и прозрачно переключается на
официальное зеркало данных **`data-api.binance.vision`** — график,
бэктест, paper-режим и подбор диапазона продолжают работать без каких-либо
настроек. **Live-торговля при региональной блокировке невозможна**: у
зеркала нет торговых (подписанных) эндпоинтов — это ограничение самой
Binance, приложение честно сообщит об этом по-русски.

## Бэктест

```powershell
# явный диапазон
python -m gridbot.backtest --symbol BTCUSDT --start 2025-01-01 --end 2025-07-01 `
    --lower 70000 --upper 110000 --levels 30 --budget 1000 --interval 1m

# диапазон из ПЕРВЫХ 20% свечей окна (без lookahead), торговля на остатке
python -m gridbot.backtest --symbol BTCUSDT --start 2025-05-01 --end 2025-07-01 `
    --interval 1h --levels 30 --budget 1000 --auto-range

# полностью офлайн, по своему CSV
python -m gridbot.backtest --data-file path\to\candles.csv --offline `
    --lower 100 --upper 110 --levels 11 --budget 1100
```

Отчёт: total return %, buy&hold за то же окно, реализованный профит
сетки, комиссии, max drawdown по equity, число сделок и кругов,
% времени в диапазоне, финальный инвентарь. Кривая equity пишется в
CSV (`gridbot/reports/` по умолчанию, флаг `--out-dir`).

## Paper-трейдинг

```powershell
python -m gridbot.paper --symbol BTCUSDT --lower 70000 --upper 110000 `
    --levels 30 --budget 1000 --poll 10
```

* Опрос `bookTicker` каждые `--poll` секунд; BUY на уровне `p`
  исполняется, когда `ask <= p`, SELL — когда `bid >= p` (то же
  консервативное ядро, что и в бэктесте).
* Состояние сохраняется в JSON (`gridbot/state/paper_{symbol}.json`)
  **после каждого события** — перезапуск продолжает с места остановки.
  Чтобы начать заново — удалите файл состояния.
* **Догон по истории**: в состоянии хранится время последнего опроса
  (`last_seen_ms`). Если при возобновлении простой длился ≥ 2 минут,
  бот скачивает минутные свечи за время простоя и прогоняет их через
  тот же честный движок (ордер, созданный внутри свечи, не может
  исполниться в ней же) — сетка «проживает» закрытый период: исполнения
  получают исторические метки времени, PnL и состояние ордеров
  соответствуют тому, что случилось бы при непрерывной работе. Свеча,
  (частично) наблюдавшаяся вживую до остановки, повторно не
  проигрывается — двойного счёта нет. Ошибка догона (нет сети, пустые
  данные) никогда не мешает обычному возобновлению — бот просто
  продолжает с текущих цен. Старые файлы состояния без `last_seen_ms`
  работают как раньше (без догона). Для **live-режима догон не нужен**:
  там ордера живут на самой бирже — после рестарта бот сверяется с ней
  и подхватывает исполнившиеся офлайн ордера (уже реализовано).
* Каждое исполнение и периодический снимок equity пишутся в
  `gridbot/logs/paper_{symbol}.log`.
* Быстрая офлайн-проверка (один цикл на синтетике, без сети):
  `python -m gridbot.paper --dry-run`.

## Live-торговля (реальные деньги)

Тот же движок, но ордера выставляются НА БИРЖУ по-настоящему
(`gridbot.live`, в приложении — переключатель «Live»). Бот **не
советует, что покупать** — он лишь исполняет сетку, которую вы сами
настроили: диапазон, уровни и бюджет выбираете вы.

### Как включить (сначала — testnet!)

1. **Testnet.** Зарегистрируйтесь на <https://testnet.binance.vision>
   (вход через GitHub), сгенерируйте ключи и погоняйте бота на
   «игрушечных» деньгах:

   ```powershell
   $env:GRIDBOT_API_KEY = "..."      # ключи ТОЛЬКО через переменные
   $env:GRIDBOT_API_SECRET = "..."   # окружения, не через аргументы
   python -m gridbot.live --symbol BTCUSDT --lower 70000 --upper 110000 `
       --levels 20 --budget 100 --testnet
   ```

2. **Mainnet** — только когда testnet-прогон вас устроил:

   ```powershell
   python -m gridbot.live ... --mainnet      # спросит подтверждение YES
   python -m gridbot.live ... --mainnet --yes  # без вопроса (для скриптов)
   ```

   В настольном приложении: режим «Live», сеть «Mainnet», красное окно
   подтверждения — нужно ввести название пары (например `BTCUSDT`).

### Создание API-ключей (важно!)

* Права ключа — ТОЛЬКО **«Enable Reading» + «Enable Spot & Margin
  Trading»**. **НЕ включайте вывод средств (Enable Withdrawals)** — боту
  он не нужен: в коде вообще нет эндпоинтов вывода/перевода, это
  сделано сознательно.
* Включите **IP-whitelist** (ограничьте ключ адресом машины, где
  работает бот).
* Начинайте с **малого бюджета**, который не жалко потерять.
* Желательно держать немного BNB и включить «оплату комиссий BNB»,
  иначе комиссия списывается купленной монетой и на парной продаже
  может не хватить количества (бот залогирует отказ и будет повторять).

### Как это работает

* На старте бот проверяет баланс котируемой валюты (нужно ≥ бюджета),
  покупает по рынку базовый актив под SELL-уровни и выставляет все
  лимитные ордера сетки с детерминированными `clientOrderId`
  (`gb<run_id>-<номер>`). Если рыночная покупка не удалась — запуск
  отменяется ДО выставления лимиток.
* Каждые `--poll` секунд (по умолчанию 5) бот одним запросом сверяет
  открытые ордера: исполненный ордер попадает в движок, парный ордер
  выставляется на биржу. Частично исполненные ордера ждём до полного
  исполнения.
* **Жёсткий лимит бюджета**: котировка «под риском» на бирже (рыночная
  покупка + купленное − возвращённое продажами + номиналы открытых
  BUY-лимиток) никогда не превышает `бюджет × 1.001`; нарушающий ордер
  не выставляется и логируется.
* Состояние сохраняется в JSON после каждого изменения (атомарно).
  После перезапуска бот сверяется с биржей: применяет исполнения,
  случившиеся офлайн (в порядке `updateTime`), и довыставляет
  недостающие парные ордера.
* Если ордер отменили **на бирже вручную** — бот считает это внешним
  вмешательством и безопасно останавливается (остальные ордера
  снимает).
* **Стоп** (`Ctrl+C` в CLI, кнопка в приложении) по умолчанию отменяет
  все ордера бота на бирже; флаг `--keep-orders` (галочка «Оставить
  ордера» в приложении) оставляет лимитки на бирже — они продолжат
  исполняться без бота, а при следующем запуске он их подхватит.
  Закрытие окна приложения ордера НЕ отменяет (только останавливает
  опрос).
* В приложении ключи хранятся зашифрованными Windows DPAPI
  (`credentials.bin` в данных приложения), секрет никогда не
  показывается и не логируется; CLI берёт ключи только из переменных
  окружения `GRIDBOT_API_KEY` / `GRIDBOT_API_SECRET`.

## Ключевые параметры

| Параметр | Смысл |
|---|---|
| `--lower / --upper` | Границы сетки |
| `--levels` | Число уровней (N ≥ 2) |
| `--spacing` | `arithmetic` (равный шаг цены) или `geometric` (равный шаг в %) |
| `--budget` | Бюджет в котируемой валюте; делится поровну между уровнями (с запасом под комиссию, чтобы кэш не мог уйти в минус) |
| `--fee` | Ставка комиссии за сделку (по умолчанию 0.001 = 0.1%) |
| `--auto-range` | Диапазон из первой части окна (доля `--range-frac`, деф. 0.2) — торгуемые данные диапазон не выбирают |

Биржевые фильтры (tickSize/stepSize/minNotional) подтягиваются из
`exchangeInfo` автоматически; без сети берутся офлайн-дефолты. Если
хоть один уровень нарушает `minNotional`, конфиг **отклоняется при
создании** — увеличьте бюджет или уменьшите число уровней.

## Модель исполнения в бэктесте (без lookahead)

* BUY-лимитка по цене `p` исполняется в свече ⇔ `low <= p`;
  SELL ⇔ `high >= p`; цена исполнения — всегда цена лимитки.
* Ордер, созданный ВНУТРИ свечи (например, SELL от только что
  исполненного BUY), не может исполниться в той же свече — только со
  следующей. Это убирает внутрисвечной оптимизм двойного счёта.
* Порядок детерминированный: BUY от нижних цен вверх, затем SELL от
  верхних вниз, всё по снимку ордеров на начало свечи.
* Выход цены из диапазона: ордера просто перестают исполняться,
  статус `out_of_range_*`. Трейлинга/перецентровки нет (архитектурно
  модуль перецентровки можно добавить поверх движка позже).

## Приложение GridBot (Windows)

Тот же движок в виде настольного приложения с одностраничным интерфейсом
(настройки → бэктест → paper-режим, график цены с уровнями сетки).

* **Выбор пары**: чипы быстрых пар (BTC, ETH, SOL, BNB, XRP, DOGE, TON,
  ADA) над полем символа + автодополнение по всем спотовым USDT-парам
  Binance (список тянется с биржи и кэшируется на 24 часа; без сети —
  встроенный список популярных пар).
* **Режим сетки «От цены + шаг»**: вместо ручных границ можно задать
  только шаг между уровнями в процентах (0.05–10%) — бот возьмёт текущую
  цену и построит диапазон симметрично вокруг неё: арифметически
  (`шаг_абс = цена × шаг% / 100`, границы `цена ± шаг_абс×(N−1)/2`) или
  геометрически (равный шаг в %, `цена / r^((N−1)/2)` …
  `цена × r^((N−1)/2)`, где `r = 1 + шаг%/100`). Перед стартом/бэктестом
  интерфейс показывает подсказку «Сетка: N уровней, от X до Y (шаг ≈ Z)»
  и дальше всё работает как в ручном режиме (та же валидация).

* **Портативная версия**: `gridbot/packaging/dist/GridBot.exe` — один файл,
  скопировал и запустил, установка не нужна.
* **Установщик**: `gridbot/packaging/dist/GridBot-Setup.exe` — мастер
  установки на русском, ярлыки в меню «Пуск» и на рабочем столе,
  деинсталлятор. Ставится без прав администратора.
* Данные приложения (настройки, состояние paper, логи, кэш свечей) живут в
  `%LOCALAPPDATA%\GridBot` и переживают переустановку.
* Требуется Edge WebView2 Runtime (на Windows 11 предустановлен). Exe не
  подписан — SmartScreen при первом запуске покажет предупреждение
  («Подробнее» → «Выполнить в любом случае»).
* Пересборка из исходников:
  `powershell -ExecutionPolicy Bypass -File gridbot/packaging/build.ps1`
  (подробности в `gridbot/packaging/README_BUILD.md`).

## Ограничения

* **Live-режим есть**, но намеренно минимальный: один символ на запуск,
  paper и live взаимоисключающие, никаких эндпоинтов вывода/перевода
  средств в коде нет вообще.
* Частично исполненные ордера бот **ждёт до полного исполнения** —
  движок узнаёт об ордере только когда биржа вернула статус `FILLED`.
* Учёт (PnL, комиссии) ведётся моделью движка в котируемой валюте;
  реальные комиссии Binance списываются в купленной монете или BNB,
  поэтому возможно небольшое расхождение с балансом биржи (стартовое
  расхождение логируется).
* Одна ставка комиссии (без maker/taker-раздельно), без проскальзывания
  сверх лимитной цены в модели.
* Funding/дивидендов на споте нет.

## ⚠️ Честное предупреждение о рисках грид-стратегии

Сетка зарабатывает **только в боковике**. В устойчивом тренде вниз бот
методично **накапливает падающий актив**: каждый пробитый уровень —
ещё одна покупка, и внизу диапазона вы сидите с полным инвентарём,
купленным дороже рынка, а сетка перестаёт торговать (`out_of_range_below`).
Реализованный «профит сетки» может быть положительным при отрицательном
общем результате — смотрите на **total return и drawdown**, а не только
на счётчик кругов. Тренд вверх — упущенная прибыль против buy&hold
(инвентарь распродан по пути). Бэктест на истории не гарантирует
будущего; выбор диапазона по прошлым данным — это тоже подгонка.

## Тесты

```powershell
python -m pytest gridbot/tests -v
```

Все тесты офлайн, на синтетических свечах (сеть в тестах запрещена).
Покрыто: генерация уровней, начальная расстановка, парные ордера,
точный PnL круга, консервативное правило «не в той же свече»,
выход из диапазона, валидация minNotional, бухгалтерское тождество
`cash + base*close == budget + realized_gross + unrealized − fees`
на каждом шаге, персистентность paper-состояния, зигзаг-бэктест с
посчитанным вручную результатом.
